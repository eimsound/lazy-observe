# Issue AI 持久分析产品需求文档（PRD）

> 状态：后续功能，不属于核心可观测性闭环预生产质量轮的验收范围。

## 问题陈述

当前 Issue AI 通过进程内队列触发模型调用。队列已满、进程退出或单次调用失败时，任务只降级为日志；手工请求还可能在 HTTP 生命周期内等待模型。系统无法稳定回答某次分析是否已接管、尝试了几次、使用了什么上下文和模型配置，也无法保证租约丢失或设置关闭后迟到的响应不会覆盖当前结果。

Issue、告警和错误摄取的完成条件不应依赖外部模型。Issue AI 必须作为可选的后续能力独立交付，不得成为核心可观测性闭环达到预生产质量的前置条件。

## 解决方案

把自动和手工 Issue AI 分析统一建模为持久分析任务（Issue AI analysis job）。主服务中的 Issue AI 协调器拥有资格判定、领取、租约、上下文快照、尝试、重试、取消和结算；不感知任务的请求工作进程只执行一次已经固定的 Provider 请求。数据库保存权威任务状态、不可变上下文和调用记录，缓存租约只协调执行活性，单调接管纪元（claim epoch）阻止迟到所有者发布结果。

自动分析消费持久的 `new_issue` 生命周期事实，但在错误收件箱完成边界之外创建任务。无论 AI 任务成功、失败、取消或重试，都不得延迟错误摄取、Issue 生命周期提交或告警分发。

## 用户故事

1. 作为管理员，我可以在现有 AI 设置页配置全局 Issue AI 自动重试次数；默认在首次模型请求后重试一次，每次持久运行公开终止状态。
2. 作为管理员，我可以把 Issue AI 运行历史保留期设置为 1 至 365 天；空值继承全局日志保留期，热更新管理已有终止历史。
3. 作为项目成员，我可以通过经过审计和限流的异步操作生成或刷新分析，并在持久任务接管后立即得到可查询的任务资源。
4. 作为查看者，我可以读取最近成功分析、当前任务状态、完整 AI 上下文、准确调用记录及实际使用的 Provider、模型和 Provider 原生思考配置，而不消耗 AI 容量。
5. 作为管理员，禁用全局 AI 会停止新工作、终止性取消待处理或运行中的任务，并拒绝迟到响应；重新启用不会复活已取消任务。
6. 作为管理员，我可以明确让某个项目选择加入未来新 Issue 的自动分析；关闭项目策略不取消已经接管的任务，重新开启也不回填旧 Issue。
7. 作为运维者，只要保留同一元数据数据库和所配置的缓存语义，任务可以在进程重启、租约过期或执行者丢失后恢复，并且旧执行者不能发布陈旧结果。

## 产品与权限决策

- 同一 Issue 最多存在一个 `pending` 或 `running` 任务。重复生命周期投递、自动分析和手工请求合并（coalesce）到活动运行；终态后的手工刷新创建新运行。
- 只有成功的新运行会原子替换最近发布的分析。刷新活动、失败或取消期间继续展示先前成功结果，并单独展示新运行状态。
- 手工生成和刷新只能异步执行。`POST /api/issues/:id/ai-analysis` 必须携带 `Idempotency-Key`，完成权限、操作者/项目限流、审计以及任务创建或合并后统一返回 `202 Accepted`、稳定 `job_id`、`status`、`coalesced` 和指向任务状态资源的 `Location`。不存在同步快速路径。
- 查看者（Viewer）可以读取已发布分析和仍在保留期内的运行材料；成员（Member）与管理员（Admin）可以手工生成或刷新；只有管理员可以修改项目自动分析策略。自动创建记录系统操作者，手工写入记录管理审计，但审计不包含证据或模型内容。
- 全局 AI `enabled` 是 Provider 可用性和数据外发总闸，不表示所有项目同意自动分析。项目字段 `automatic_issue_analysis_enabled` 默认关闭且仅管理员可写；自动消费未来的 `new_issue` 要求两个开关都开启。关闭项目开关只阻止未来自动任务，不取消活动任务；重新开启不回填。全局 AI 可用时，成员与管理员仍可手工运行。
- 关闭全局 AI 会阻止创建和领取任务，把待处理任务持久改为 `cancelled`，并尽力取消运行中请求。迟到响应由条件终态写拒绝；重新开启不复活已取消任务。

## 设置与模型调用决策

- 全局设置 `issue_analysis_retry_count` 允许 `0–5`，默认 `1`，任务创建时快照。每次真实模型请求（包括结构化输出修复）消耗一次尝试；该预算独立于错误收件箱的 20 次处理预算。
- 有剩余预算时，网络故障、超时、HTTP 408/429/5xx、一般输出契约错误和 DeepSeek `insufficient_system_resource` 可以重试。认证、授权、模型缺失、上下文及其他配置故障直接终止；`finish_reason=length` 终止为 `output_truncated`，`content_filter` 终止为 `content_filtered`，无工具工作流中的 `tool_calls` 终止为 `unexpected_tool_call`，均不自动重试。
- AI 重试使用五秒初始、30 秒指数上限和等幅抖动（equal jitter）；有效的 429 `Retry-After` 或重置提示优先，最多等待五分钟。基础设施恢复和数据库结算重试使用独立的一秒初始、30 秒上限等幅抖动，不创建尝试或消耗任务预算。
- Provider、基础 URL、模型和凭据由 AI 功能共享；最大输出、Provider 原生思考、连接/总时长超时和提示词策略只作用于 Issue AI。每次尝试开始时只读取一次最新完整配置并在请求内固定，因此热更新可以影响同一任务的后续尝试。
- Issue AI 最大输出 token 默认不设置并省略 `max_tokens`；配置时至少为 `1024`，平台不设上限。连接阶段超时只覆盖 DNS/TCP/TLS，允许 1 至 60 秒、默认三秒；Provider HTTP 总超时覆盖请求开始至完整响应体读取，允许 30 至 3,600 秒、默认 300 秒，本地输出解析和数据库结算不计入该时长。
- 全局 `issue_analysis_context_budget_bytes` 允许 4 KiB 至 1 MiB、默认 24 KiB，在任务创建时快照。`issue_analysis_history_retention_days` 允许 1 至 365 或空值；空值继承全局日志保留期，热更新立即成为清理已有终态历史的策略。
- 通用 AI 设置使用普通强类型列；所选 Provider 特有设置使用一个内部 JSON 列，并由 Provider 代码声明字段、默认值、校验、表单说明和请求映射。用户不直接编辑 JSON，也不能透传未知请求字段。初始只支持 DeepSeek；`thinking.type` 与只接受 `low/high/max` 的 `reasoning_effort` 相互独立，默认启用思考且强度为 `high`。
- 管理员连接测试只使用已经保存并激活的配置，并执行真实 Issue AI 思考、最大输出和超时策略。它是受总超时限制的同步请求；失败只提供诊断，不回滚配置或禁用 AI。

## 上下文、记录与隐私决策

- 任务创建时固定 `context_cutoff_at`。首次模型调用前最多等待五秒供索引可见，然后从同项目的 Issue、数量有界的近期 occurrence 与符号化堆栈、最新 occurrence 的准确 Trace 和 trace-ID 日志，以及数量有界的发布/部署/标签分布和相关服务时间窗指标中构建上下文。回放 DOM、源代码和任意项目范围搜索不属于初始上下文。
- 协调器在当前接管纪元下原子保存完整不可变上下文、摘要和省略清单；快照只能完整存在或不存在。重试复用同一快照，不吸收截止点后的事件；终态刷新创建新快照。
- 上下文按稳定顺序确定性裁剪且不调用额外模型：Issue 标识与最新错误/符号化栈、准确 Trace/spans/trace-ID logs、较旧 occurrence、发布/部署/标签分布、相关服务指标。省略清单按证据类别公开候选、纳入和省略的条目数/字节数及原因。
- 裁剪控制相关性和体积，不是隐私过滤。服务器把已经汇总且未被容量裁剪的数据原样发送给 Provider；SDK/客户端采集与脱敏决定什么数据能够到达服务器。产品文档说明这一责任，但全局启用、项目自动化和手工生成不增加强制确认、载荷预览或专门隐私警告 UI。
- 所有事件、日志、标签和未来 MCP 工具结果都是不可信数据，不是指令。模型请求在结构上隔离可信指令与带类型、明确分隔的数据，系统策略禁止执行数据中的命令；输出必须通过严格的字段、数据库模式和长度校验。初始分析没有工具。
- 每次请求前保存精确应用层调用：系统提示词、消息、完整上下文和公开模型参数；响应后保存公开内容、工具调用、Provider 原始 `usage` JSON、可空规范化 token 维度、完整性、Provider 请求 ID 以及解析结果或错误。缺失维度保持未知而不是零；不计算任务级 token 汇总，也不保存、展示或估算货币成本。
- 成功响应正文上限为 8 MiB；超限终止为 `response_too_large` 且不自动重试。凭据、密文、授权值、传输请求头、所有者令牌和未返回给应用的 Provider 内部信息不得进入产品记录、日志或读取 API。
- 运行历史到期时删除完整上下文、调用记录、读者可见配置、运行、尝试和失败诊断，但不删除最近成功发布的 Issue 分析；该投影保留到下次成功发布或 Issue 本身被清理。

## 持久执行决策

- 主服务的 Issue AI 协调器拥有完整任务生命周期。请求工作进程公开同步且不感知任务的 `Execute(ctx, invocation) -> provider result`，只执行一次已固定请求；它负责 Provider HTTP 和响应协议解析，但不读取或修改任务/尝试，不持久化、不重试、不解析 Issue AI 输出契约，也不决定调度或终态。
- 数据库是权威队列。符合条件的任务以 `eligible_at` 为统一 FIFO 键，按 `(eligible_at, created_at, stable_id)` 使用有界键集分页扫描；未到期重试不阻塞已就绪任务，租约冲突只跳过。协调器在启动、事务提交后通知及每 30 秒兜底扫描，不引入 PostgreSQL `LISTEN/NOTIFY`、SQLite 专用唤醒、最早到期计时器或逐任务等待 goroutine。
- 初始一体化部署只运行一个应用进程。`worker.issue_ai_concurrency` 允许 `1–64`、默认 `1`，修改需重启；零无效，停用应使用全局 AI 开关。初始不设置全局/逐项目并发配额、手工/自动优先级或公平调度；独立部署的分离工作进程、多副本和集群容量语义不属于初始交付。
- 协调器通过缓存端口取得带随机所有者令牌的可续租租约。`worker.issue_ai_lease_duration` 默认 30 秒，`worker.issue_ai_lease_renew_interval` 默认 10 秒；两者必须为正且续租间隔严格小于租约时长，变更需重启。未启用 Redis 时使用真正按 TTL 过期的内存实现；明确启用 Redis 后启动连接失败会中止，不回退内存，运行时故障会停止新领取且不回退。
- 领取严格依次执行候选读取、缓存租约、数据库条件接管并递增 `claim_epoch`。每次获取使用新的随机令牌；续租和释放比较完整令牌。模型请求前才创建尝试并复制当前纪元；领取和上下文准备不消耗尝试。发布、重试和终态结算都以当前纪元条件事务原子写入任务、尝试和最近成功指针，提交后才停止续租并释放租约。
- 接管时发现前一所有者未结算尝试，会在同一领取事务中把它结算为已消耗的 `lease_lost`；仍有预算时正常退避，否则终止失败。旧纪元、租约丢失或关闭后的迟到响应不得发布。进程关闭时停止新领取并立即取消在途请求，不提供排空窗口；已开始尝试仍消耗预算。
- Provider 响应已完整读取但数据库结算暂时失败时，协调器保留同一响应和租约并重试同一事务，不再次调用 Provider或消耗额外预算。第一次结算失败会打开进程级背压门，暂停新请求；全部保留结算提交后关闭并立即扫描。陈旧纪元丢弃响应。
- 初始 DeepSeek 调用启用流式传输。推理和最终内容分流；协调器至少每 250 毫秒或缓冲达到 16 KiB 时持久化批次。只有已提交批次实时可见；每个事件以 `(attempt_id, seq)` 唯一，SSE GET 先按 `after_seq` 重放后再发送新事件，不引入 WebSocket。中断流的已提交数据保留为不完整/失败诊断，绝不成为当前分析。

## UI 与诊断决策

- Issue 页面分别展示最近成功分析和当前运行状态。项目可读用户可以查看任务终态错误、完整上下文、省略清单、准确调用记录、实际 Provider/模型/思考配置、尝试序号/时间、语义化 `lease_lost`、接管和下次重试时间。
- `claim_epoch`、应用副本身份和所有者令牌不属于产品 API/UI。管理员通过内部指标和不含令牌的日志诊断租约冲突、续租失败、接管和结算重试。
- AI 设置页以类型化控件公开重试次数、上下文字节预算、可空历史保留期和 DeepSeek 设置；空保留期显示继承的日志保留期，缩短保留期前警告旧历史可能到期。页面不提供 JSON 编辑器。

## 测试决策

- 最高产品测试边界是 Gateway HTTP、真实 SQLite 元数据实现和 Issue UI；双方言事务、领取和回滚行为再通过选择启用的 PostgreSQL 测试验证。测试断言公开状态、持久结果和可见 UI，不断言私有调用次数。
- 使用可阻塞假 Provider、假时钟、内存 TTL 缓存和 Redis 契约测试证明：任务幂等创建、单活动运行、异步 `202`、预算边界、错误分类、FIFO、并发上限、租约续期/接管、纪元隔离、重启恢复、流事件重放、结算背压和迟到结果拒绝。
- 使用真实 Issue/Trace/log fixture 证明固定完整上下文、确定性裁剪、省略清单、项目隔离、调用审计、密钥排除、不可信数据隔离及严格输出契约。
- 设置测试证明所有数值边界、任务快照与逐尝试热读取、DeepSeek 强类型字段、空值继承保留期、全局/项目开关、权限、限流和审计。
- Issue AI 最终失败或取消不得改变已经提交的 Issue、告警或最近成功分析。

## 交付顺序

1. 建立持久任务、异步 API 和单活动运行，先证明 Issue/告警不受模型成败影响。
2. 固定上下文与调用记录，接入可配置的单次 Provider 请求和严格输出契约。
3. 增加重试预算、错误分类、流式历史和 UI 诊断。
4. 增加租约、接管纪元、恢复扫描、结算背压和故障注入证据。
5. 增加项目自动分析策略、历史清理、完整权限/审计以及最终端到端验证。

## 范围之外

- 核心可观测性闭环预生产质量的任何验收门禁；该功能在核心预生产工作完成后独立排期和验收。
- 让 Issue AI 成为错误摄取、Issue 生命周期或告警分发的完成条件。
- 独立部署的请求工作进程拆分、多应用副本共享租约、集群容量配额和公平调度。
- 回放 DOM、源代码或任意项目范围搜索进入初始上下文。
- AI 专用的服务端遥测字段脱敏、强制确认、发送前预览或专门隐私警告 UI。
- 写入工具或 MCP 查询。未来只读 MCP 必须使用逐任务短期能力，强制项目/Issue/截止点/信号/工具作用域及调用、时间窗、行、字节、token、时长预算，并审计查询与结果摘要。
- 货币成本估算、任务级 token 汇总、WebSocket 传输、旧同步 API 兼容路径或发布前旧数据库兼容。
