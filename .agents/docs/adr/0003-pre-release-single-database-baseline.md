# 首个正式版本前使用单一可变数据库基线

## 背景

lazy-observe 仍处于首次发布前（pre-release）的早期开发阶段。目前没有受支持的已安装版本矩阵，也不承诺升级由早期开发提交创建的数据库。在这个阶段维护包含 21 个步骤的迁移链，只会保留不属于当前产品模型的过渡名称和兼容状态。

## 决策

- SQLite 和 PostgreSQL 各自只包含一个权威的 `001_baseline.sql`，用于描述当前完整 schema。
- schema 变更直接替换两种方言的配对基线，不追加迁移版本。不兼容的 schema 变更后，必须删除并重建开发数据库。
- 启动迁移器保留 PostgreSQL advisory lock（咨询锁）、事务化基线创建、校验和验证、就绪失败处理，以及唯一一行 `schema_version`。该记录只标识基线，不代表受支持的数据库升级历史。
- Ent 继续用于生成 schema 和查询代码。Ent 自动迁移与 Atlas 都不属于运行时数据库管理路径。
- 不得仅为兼容早期开发提交创建的数据库而保留别名、数据回填、过渡字段或旧枚举值。

## 发布边界

在首个受支持版本发布前，维护者必须冻结基线，并通过新的 ADR 定义只追加的前向迁移（append-only forward migrations）及受支持的升级/回滚契约。只有冻结后创建的迁移才成为不可变的发布产物。

## 后果

现有开发数据库可随时丢弃，schema 变更后也可能无法启动。运维者和贡献者应重建数据库，而不是期待原地升级。作为交换，基线可以直接匹配当前领域模型，不背负发布前兼容债务。
