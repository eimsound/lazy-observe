# pitfalls

基于审查沉淀的高频缺陷模式。审查代码，或修改对应改动面的逻辑与配置时（仅改错字/注释/纯文档可跳过），先确认通用不变量，再核对对应子清单；具体行为以当前源码为准。

## 全仓通用不变量

1. **凭据零泄漏**：错误信息、审计与投递 `last_error`、前端列表卡片、弹窗状态、SDK 异常/`repr`/示例以及跨源重定向一律脱敏或剥离令牌与密钥。
2. **入口有界且 fail-closed**：所有外部写入与查询路径强制项目隔离、请求体与解压尺寸上限、批大小与高基数标签规范化、客户端时间戳钳位、上游超时与 body drain。
3. **跨层契约同源对齐**：后端 DTO/HTTP 状态码、前端展示单位与错误语义、MCP 工具及四端 SDK 协议保持一致，由真实端到端或契约测试守护，不靠过时 stub 掩盖漂移。
4. **并发与多副本可恢复**：共享可变状态全程受锁或封装为不可变快照，后台循环捕获 panic 并响应取消信号，HA 租约使用全局唯一 owner 与单调纪元且被拒时按 `AGENTS.md` 记录 `slog.Warn`。
5. **静默降级与可靠发布**：SDK 内部异常静默降级且不中断宿主业务；部署与 CI 链路保持镜像/产物一致、最小权限与传递依赖边界隔离。

## 完成判据

提交或给出审查结论前，核对命中的子清单条目，确认未重演已知缺陷。

## 维护规则

- **准入**：同时满足三点才收录——真实踩过（附合入 PR 或已完成 Issue 号）、同类改动可能复现（非一次性业务 bug）、现有 linter/测试抓不到。
- **毕业与验活**：能写成 linter、契约测试或 CI 断言的规则，先落自动化检查再从清单删除；修订时先删源码中已失效的路径或符号。
- **容量上限**：`backend.md ≤ 35 条且 ≤ 14 KB`，其余子清单 `≤ 20 条且 ≤ 6 KB`；超限先合并或晋升为自动化检查，再新增。
- **更新路径**：新增自动化检查的 PR 可同步删除已覆盖条目；其余修订由 Review 输出 `## Pitfall Signals`，在 `/skill:retro` 触发时批量处理（不在普通业务 PR 中零散改）。
