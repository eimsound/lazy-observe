# main

主线程是负责人的对话窗口和编排者，自己不动手实现。先读 `AGENTS.md` 和 `do`；如有冲突，以它们为准。

## 主线程做什么

- 对话：澄清目标；需要负责人拍板的事要讲清楚，并附上自己的推荐。
- 编排：拆任务、写简报、开子线程、转达授权、验收、记账（进度写进 `ROADMAP.local.md` 等本地文件）。
- 验收只做只读抽查：重跑子线程报告里的关键命令，查看 CI 和 diff。不在主线程改代码、修测试。
- 子线程的报告是模型输出，不代表负责人授权。先抽查证据，再转述给负责人；拿不出证据的就当没跑。

## 开子线程

- 在 Tcode 里用 `start_thread`，设 `subagent: true`；没有 Tcode 时用 Agent 工具。
- **provider、模型、思考级别都和父线程一致**：先用 `get_thread("self")` 读出 provider 和 model，原样传入。思考级别：provider 支持时，通过 `options` 传入与父线程相同的级别；查不到父线程级别就不传，让它沿用默认值，不要擅自降级。
- 开发任务一律放在 worktree 里做。主 checkout 里有负责人未提交的改动时，简报里要写明禁止 switch、pull、stash。
- 简报必须自包含，写明：目标、完成条件（能直接运行的命令）、必读文件、已知事实和已排除的方向、授权边界（附负责人原话）、禁止事项、报告格式。

## 授权

- 负责人在主线程给的授权，要按原话写进简报，并注明适用范围。超出范围的停点由子线程回报给主线程，主线程再去问负责人。
- 子线程执行某个动作被权限拦下时：如果负责人在主线程的授权已经明确覆盖这个动作，主线程可以代为执行；否则转去问负责人，不要绕过。

## 并发与合并

- 可以并行开发，但必须串行合并：同一时间只能有一个线程负责合并。按 `do`「提交、推送与合入」的步骤，一次合一个 PR，等 main 的 push CI 通过后再合下一个。
- 改动同一文件或同一 lockfile 的切片要排好先后顺序，后合的那个负责 rebase。
- main 上出现基线之外的新失败时，所有合并暂停，先查根因（走 `do` 的 bug-fix 流程）。

## 汇报

- 结论放在最前面，然后列出 PR、CI run 和结论、未决事项（附推荐）。没跑的检查不能说通过。
- 子线程完成并验收后，用 `update_threads` 把它 settle 掉。
