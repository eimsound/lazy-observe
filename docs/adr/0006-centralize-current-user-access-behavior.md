# 将当前用户访问行为集中到账户接缝（account seam）之后

Gateway 当前同时拥有登录防护、凭据校验、元数据/Redis 会话路径选择、当前用户自助行为、用户 API Token 编排和 HTTP 转换；这使安全规则与失败顺序散落在处理器中，并让零配置与多应用副本拓扑呈现不同的会话接口。我们决定建立独立的账户模块（account module）：Gateway 只保留 HTTP 解析、Cookie、CSRF、状态码与 JSON 映射，账户模块通过行为级接口拥有当前用户的登录、认证、退出、资料、密码、会话和用户 API Token 行为。

## 决策

- 账户模块拥有登录的来源与账号限流、临时锁定、等时失败、凭据校验、会话创建、`last_login_at` 更新顺序、稳定错误和安全审计事实。Gateway 只向它提供规范化用户名、密码和来源地址，不掌握持久化或共享状态的调用顺序。
- 账户模块拥有当前用户的读取与资料更新、密码修改、会话列举/撤销、退出，以及用户 API Token 的列举/签发/撤销/认证。管理员项目、用户和项目 API Token 行为继续由管理模块（management module）拥有；项目 API Token 认证、项目选择和 RBAC 的 HTTP 中间件不并入本决定。
- 账户模块内部定义一个完整的会话端口（session port）；元数据会话与 Redis 共享会话是两个显式适配器。生产启动根据部署拓扑构造其中一个适配器并显式注入，不使用 `nil`、运行时类型断言或从宽泛的 Store 自动推断能力。
- 两个会话适配器返回相同类型的不透明字符串引用（opaque string reference），用于会话列举/撤销接口公开的 `id`。该引用不是会话令牌，也不能用于认证；项目处于首次发布前阶段，不保留元数据数字 ID 的兼容响应或回退路径。
- 元数据实现继续拥有 Argon2id、用户/会话/Token 持久化、Ent、双方言差异和数据库事务；账户模块不导入生成的 Ent 代码，也不增加逐表仓储接口。内存与 Redis 的限流、锁定和会话适配器继续共享现有状态契约。
- 账户模块只有在凭据、会话创建和必要的元数据更新都完成后，才返回可交付的登录结果。创建会话后的失败必须尝试撤销新会话，并返回稳定的 unavailable 错误；不得把部分完成报告为成功。
- 密码修改成功的 HTTP 结果只有在密码已经提交且其他会话已经撤销后才能返回。跨元数据/Redis 写入不宣称事务原子性：如果密码提交后撤销会话失败，账户模块返回稳定的 unavailable 错误和安全审计事实，不静默返回成功，也不伪造密码回滚。
- 会话认证以元数据中的当前用户状态为准。Redis 会话可以缓存用户 ID 和展示字段，但不能让已删除用户或角色已变更的用户继续获得旧 RBAC 权限。
- 账户模块只返回允许清单内（allow-listed）的审计事实；Gateway 补充 HTTP 方法/路径和请求操作者，并沿用现有尽力而为（best-effort）的审计持久化语义。密码、会话令牌、CSRF Token 和用户 API Token 密钥不得进入审计事实。

## 已考虑的方案

- **独立账户模块与两个显式会话适配器（采用）**：在一个行为级接缝后集中安全规则和失败语义，同时让 SQLite 元数据会话与 Redis 共享会话遵守相同接口。两个真实适配器使该接缝不会成为仅为测试制造的虚假抽象。
- **扩张管理模块（拒绝）**：管理员替其他用户执行的管理行为，与当前用户的认证、自助凭据和会话生命周期具有不同的操作者、授权和失败语义；合并会降低刚建立的管理模块的代码局部性。
- **仅提取 Gateway 辅助函数（拒绝）**：辅助函数仍要求 Gateway 选择会话后端、组合元数据/共享状态顺序并解释部分失败；即使删除辅助函数，复杂度也不会集中回一个具有足够收益的模块。
- **把所有行为下沉到元数据 Store（拒绝）**：Redis 会话、共享限流和锁定不是元数据持久化；这还会让元数据实现拥有 HTTP 登录安全策略，违背 ADR 0004 的职责归属方向。

## 后果

- Gateway 必须显式接收账户模块；目标行为迁移后，旧 `ManagementStore`、`CredentialStore`、`UserAPITokenStore` 和 `SessionLister` 运行时发现路径会被收缩，不保留兼容适配器。
- 测试优先穿过 Gateway HTTP 接口；账户接口测试使用真实 SQLite 元数据 Store，并对元数据会话适配器与 Redis 会话适配器运行同一组行为断言。测试替身只用于注入明确失败，不断言内部调用次数。
- 当前 `/api/auth/sessions` 的元数据数字 `id` 将变成后端无关的不透明字符串；其他 `/api/auth` 状态码、Cookie/CSRF 属性、一次性 Token 密钥、RBAC 和审计字段保持现有契约。
- 本决定不增加 MFA、Passkey、CAPTCHA、会话滑动续期或持久跨存储补偿队列（durable cross-store compensation queue），也不修改元数据基线。
